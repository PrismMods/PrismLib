# Facet 0.2 (plan 7) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `Facet.0.2.dll` with the parts the Prism suite UI needs, skinning hooks that let a consumer supply every look and size, a preview host pane, an animation speed and a wheel tick shared across Facet versions, and Chinese and Japanese font fallback.

**Architecture:**
- **A `Theme` now carries the whole look.** It keeps its colours by `Role` and gains `Sizes` (radius, lines, spacing, row heights, type scale, control sizes) and `Looks` (one `Look` per part element). Every part reads `Theme.For(element)` when it builds, so a consumer's theme restyles every part without forking it. `Theme.Dark` keeps Facet 0.1's look, and the global `Facet.Tokens` is deleted.
- **New parts are `Controls` methods** that take `Bind`/`Options` and register with the Refresher and the search index, like today's rows. `Tabs`, `Nav`, `Slider` and `Dropdown` are extended rather than duplicated.
- **Cross-version state** gains `Facet.AnimSpeed`, `Facet.WheelStamp` and Coord entry slot 9. Their logic, the CJK font tables, `Sizes` and `Looks` are plain BCL code in `Facet/Core`, so the offline test covers them.

**Tech Stack:** C# `netstandard2.1` (R8), UnityEngine.Modules 2022.3.0 reference assemblies, `dotnet build`, `mcs` + `mono` for `./test.sh`, the Gallery mod through `tools/ingame.sh` (macOS rig: MelonLoader + UMMBridge).

**Spec:** `PrismLib/docs/superpowers/specs/2026-11-07-prism-suite-ui-design.md`, especially "The suite look", "What Facet grows" (items 1–6 and **Version**), "Constraints" and "Testing". The engine spec `2026-11-06-facet-ui-engine-design.md` still binds everything it does not override. Read both, and `Facet/CLAUDE.md`.

## Review Focus

1. **Two mods tick the wheel in one frame, and the first one passes a zero delta** (its read was gated). The window must scroll exactly one notch, not zero and not two. Pinned in Task 3.
2. **The animation speed changes while windows are open** (the `anim.duration` setting moved live). The next fold, tab switch and hover use the new speed. Speed 0 leaves the end state in the same call, never a half-drawn one. Pinned in Task 2.
3. **One consumer's skin on the same loaded Facet.** Prism's suite sizes must not leak into another consumer's window (an outside mod, the Gallery), and a write to `Theme.Dark.Sizes` changes nothing. Pinned in Tasks 5 and 6.
4. **A translated upper-case header** (a card title, a rail group) is translated first and upper-cased after. It stays upper-case through a relabel, and Hangul and Han text pass through unchanged. Pinned in Task 6.
5. **A preview whose consumer throws, or whose page or window goes away while it is showing.** `Hide` runs once, no tick follows, nothing escapes, and reopening calls `Show` again. Pinned in Task 10.

### Task 2: The animation speed, shared across versions, and hover fades

**Files:**
- Create: `Facet/Core/Motion.cs`, `Facet.Mod/AutoTest.Parts.cs`.
- Modify: `Facet/Anim.cs`, `Facet/Paint.cs`, `tests/FacetTest.cs`, `Facet.Mod/AutoTest.cs` (`partial`; `Start` runs each new section after `SectionForm`).

**Interfaces:**
- `internal static class Motion`:
  - `const string Key = "Facet.AnimSpeed"`;
  - `static float Speed { get; set; }`, stored in `Shared.Get(Key, () => new[] { 1f })` (a `float[1]`);
  - `static int Scale(int ms)` = `Speed > 0 ? (int)Math.Min(ms * (double)Speed, 60000) : 0`. NaN, 0 and negative speeds are instant.
- `public static float Anim.Speed { get; set; }` is now a property over `Motion.Speed`; it was a field.
  - Plan 8 writes `Anim.Speed = ms / 120f`.
  - A Facet 0.1 copy keeps its own field, so its windows run at speed 1, as the spec says.
- `public const int Anim.Hover = 60`: hover and press feedback, half of `Fast`.
- Every `Anim` duration and `Paint.Flash` go through `Motion.Scale`.
- **Hover fades.** An element `Paint` hooks (its Look has a hover, pressed or focus state) fades `background-color`, `color` and the border colours over `Motion.Scale(Anim.Hover)`.
  - It uses UI Toolkit's inline `style.transitionProperty` and `style.transitionDuration`.
  - They are set when the element is hooked, and set again on its next hover when the speed has changed since. Store the speed used in Paint's `State`.
  - `Flash` sets the element's duration to 0 while it runs and restores it after, because a transition would smear the per-frame flash.

### Task 3: The wheel, counted once per frame across mods and versions

**Files:**
- Modify: `Facet/Core/Coord.cs`, `Facet/Input.cs`, `tests/FacetTest.cs`, `Facet.Mod/AutoTest.Parts.cs`.

**Interfaces:**
- Coord entry slot **[9]** is an `Action<float, float, float>`: wheel(x, y, delta) for this version's topmost visible surface. Its body is today's `TickWheel` loop calling `Skin.Wheel`. Update the slot list in Coord's comment.
- `Coord.Wheel(List<object[]> entries, float[] stamp, int frame, float x, float y, float delta, Action<string> log) -> bool`:
  - `|delta| < 1e-6`: returns false and leaves the stamp alone. A gated zero read does not use up the frame.
  - `stamp[0] == frame`: returns false.
  - Otherwise it sets `stamp[0] = frame`. The entry with the highest slot-0 top (≥ 0) takes the wheel: its slot 9 runs and it returns true.
  - A top entry too short for slot 9 (Facet 0.1) takes it by doing nothing, because its own callers drive it. Returns false.
  - A throw is logged once, as in `Any`. Returns false.
  - It walks the list by index under its lock and allocates nothing.
- `Input.TickWheel(Vector2 screen, float delta)` keeps its signature. Its stamp is `Shared.Get("Facet.WheelStamp", () => new[] { -1f })`.
  - Quartz's `FacetBridge.TickWheelImpl` gate can go (plan 10).
